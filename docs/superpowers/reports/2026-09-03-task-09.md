The 180° cases were checked numerically rather than by inspection, because `Math.sin(Math.PI)`
is 1.22e-16 rather than 0: the needle's `y2` lands at 55.999999999999993, `rise` comes out a
positive 7.1e-15, and `atan2` therefore returns `+π` rather than `−π`. Had the rounding gone the
other way the helper would have read −180 and the test would have failed for a reason that has
nothing to do with the design. Ran it in node before writing the implementation; it returns 180.

## Deviations from the plan's snippets

None of these change behaviour; they are placement and coverage.

1. **`angleOf` sits with the other test helpers** (beside `textOf`) rather than in the appended
   block, so the file keeps one helper section.
2. **`buildSvg` sits beside `buildUnit`** in `src/popup.js` rather than immediately above
   `renderPressure`. It is not pressure-specific — Tasks 10 and 11 both need it — so it belongs
   with the other element builders, not inside the barometer's run of code. **Tasks 10 and 11:
   it is already there, near the top of the module, with the same
   `buildSvg({ attributes, document, name })` signature the plan specifies.**
3. **One extra test**, `renderUnavailable strikes the instruments a successful render left
   standing`. The plan adds the two `replaceChildren()` calls to `renderUnavailable` with no test
   behind them, and a test on a fresh document would pass vacuously (the groups start empty). The
   added test renders successfully first, then calls `renderUnavailable` against the same
   document — which is the real sequence (popup opens, refresh fails) and the only one where
   those two lines do anything.
4. Comments added on the new markup block, on `buildSvg`, and on the two `renderUnavailable`
   lines, per the repo's comment-the-why rule.
