## Deviation from the plan's code sample

One, and it is a code-rule fix, not a geometry change: the plan's `LID` object literal listed its keys
`centres, left, right, rise, radius`. `~/.claude/rules/objects.md` requires alphabetized properties, so the module
writes `centres, left, radius, right, rise`. Values are identical.

`toLayer` returns `{ far, ...shape }`, which is not alphabetized; the object spread bounds what "to the extent
possible" can reach here, and the alternative (destructure the shape to re-list four keys) is more code for no
readability gain. Left as the plan wrote it.
