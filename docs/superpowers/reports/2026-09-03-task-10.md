## Plan corrections made (plan file edited alongside the code)

1. **Z-order: the dashed base paints last, not first.** The plan's step 4 wrote
   `replaceChildren(dash, ...layers)` with the comment "Layers land over it". The canvas
   (`57afcd6c`) draws the `<line>` *after* the layer `<g>`s in all five sky variants, and the OVC case
   makes it decisive: the lid rect runs from `y − 2.88` to the foot of the plot, so a base drawn first is
   buried entirely — exactly the sky where the computed base is the only quantitative thing on the plaque.
   Corrected in the plan's snippet, its comment, and covered by a new test,
   `render paints the computed base over the layers rather than under them`.
2. **The plan's `renderUnavailable` test was vacuous.** Built on `popupDocument()`, it asserts
   `#sky` is empty in a document where nothing has ever rendered — it passed before any implementation
   existed. Replaced with the same assertion inside the existing
   `renderUnavailable strikes the instruments a successful render left standing`, which renders first.
   Verified it goes red with `renderSky` wired into `render` and the clear omitted from `renderUnavailable`.
3. **Helper placement.** The plan said "add above `renderComfort`". The file is ordered by the plaques'
   page order (dewpoint, cloud, wind, pressure), so `buildLayer`/`renderSky` went *below* `renderComfort`
   and above `renderWind`. Plan snippet updated, and noted there that `buildSvg` already exists near
   `buildUnit` at the top of the file.
4. Two CSS comment fixes: the palette reference pointed at a `palette.md` this repo does not carry, and the
   layer comment called the plaque ground `--panel`'s neighbour when the plaque's own surface is `--tile`.
