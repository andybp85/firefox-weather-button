## Beyond what the plan named

1. **`test/observation.test.js`'s fixture test** (`toViewModel renders the newest fixture observation`) also asserted
   on `clouds`. The plan's Step 1 named only "the three tests that assert on `view.clouds`" and listed two; this
   `deepEqual` over the whole view model was the fourth reference and had to change too. Its expectation is now the
   sorted list `BKN 25000 / FEW 20000 / FEW 7000` (the fixture reports FEW 7000, FEW 20000, BKN 25000).
2. **Two new popup tests.** Step 4 adds `describeCloudLayers` but the suite had no assertion on `.ambient-clouds` at
   all, so the function would have landed untested — against test-first. Added:
   - `render writes the cloud layers high to low with thousands separators` → `SCT 25,000 · BKN 4,500`
   - `render calls a sky with no reported layers clear` → `clear`

   Both re-derived from the spec's header rule (line 130: layers high to low, thousands separators, joined ` · `,
   `clear` when there are none), not from the plan's prose.

No other consumer of `view.clouds` existed: `src/popup-main.js`, `src/button-icon.js`, `src/model.js` and
`docs/icon-preview.js` never read it. `src/ui.css` keeps `.ambient-clouds` (Task 8 owns the header's restyle).

## Concerns

- **One-off flake in `test/popup-main.test.js`.** On one run, `a popup reopened inside the TTL serves both the series
  and the forecast from cache` failed with `#dewpoint` reading the `—` placeholder — i.e. `main()` threw and the
  terminal boundary rendered the unavailable footer. Not reproducible: 10 further runs of that file with the change
  applied and 8 on the stashed pre-change tree were all green, as were 6 full-suite runs. The file drives
  `popup-main.js` through `globalThis.document`, which every case overwrites, so a late-resolving promise from an
  earlier case can render into the current case's document; that is the most likely mechanism and it predates this
  task. Worth watching, not worth chasing here.
- `describeCloudLayers` uses the ambient locale (`new Intl.NumberFormat()`), so the new popup assertions on `25,000`
  are locale-dependent. This follows the plan and matches `HOUR_FORMAT`'s existing habit in the same module.
